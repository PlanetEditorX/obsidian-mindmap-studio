# MindMap Studio for Obsidian

MindMap Studio 是一个本地优先的 Obsidian 思维导图插件。它使用独立的 `.mindmap` 文件保存数据，并让导图、大纲、文章和通读四种视图共享同一棵节点树。插件支持富文本、图片、表格、代码、子导图、全局搜索、主题、导入导出和只读模式。

最低 Obsidian 版本：`1.5.0`。

## 功能概览

### 四种同步视图

- **导图模式**：可缩放画布、分支布局、拖放重组、节点尺寸、折叠与多选。
- **大纲模式**：按层级编辑标题、备注、任务、图片、表格和代码。
- **文章模式**：将当前物理导图呈现为带编号、目录和章节导航的文档。
- **通读模式**：按父子导图关系连续合并章节，适合整本阅读。

任一视图中的修改都会写回同一份 `MindMapDocument`，不会产生四套独立内容。

### 大型文档性能

- 导图实测尺寸重排只执行一次权威 `computeLayout()`，不再在其内部碰撞消解完成后重复跑第二次碰撞与边界重算；碰撞扫描利用按节点顶部排序的结果，一旦后续节点已经满足纵向间距就提前结束当前扫描。工具栏可用性刷新也只遍历一次节点树并复用共享上下文，分帧节点排序则预先计算视口分组、聚焦次序和距离，避免排序比较器反复做几何判断。
- 导图画布为已经挂载的节点维护 `nodeId → HTMLElement` 索引；渐进挂载、拖拽、实测尺寸采集、FLIP 动画、行内编辑与单节点刷新直接按 ID 访问节点 DOM，不再为每个节点或每次指针移动重复扫描整个节点层。选择样式同步保存上一次已应用的选择集合，普通单选/多选只更新发生变化的 ID；只有大纲/文章 DOM 重建后才做一次全量同步。
- 编辑器还为当前节点树维护一次完整渲染周期内复用的 `NodeTreeIndex`：按 DFS 顺序保存节点列表，并建立 `nodeId → node`、`nodeId → parent` 与可折叠状态索引。普通选择、工具栏、键盘导航、节点编辑和删除回退直接查索引；拖放合法性与多选顶层分支过滤沿 `parentById` 向上判断祖先，不再为每个候选节点重复扫描整棵子树。结构修改完成后的下一次完整渲染统一重建索引，纯内容编辑继续复用当前索引。
- 文章编辑后的跨文件上下文刷新按 `none / content / structure` 分级：图片、表格、代码、样式、尺寸和折叠等不影响目录语义的本地变化只保存当前文档；标题文字等内容变化只使用已经加载的 `readingSections` 在内存中重算目录标题、编号与 breadcrumb，不重新读取父/子 `.mindmap`；节点增删移动、子导图关系和文章编号变化才执行完整文章族重建。轻量刷新若发现目录数量或层级发生变化会自动回退完整构建；异步完整构建期间若文档修订已变化，则丢弃旧快照并立即重建，避免旧结果覆盖新编辑。
- 只有进入导图模式时才计算完整布局；同一次布局会缓存子树高度，深层或链式节点不再重复递归计算。节点 DOM 仍按“当前节点关系链 → 当前视口 → 相邻视口 → 其余区域”分帧挂载，保证连接线结果不变。
- 文章模式采用目标窗口渲染，并缓存父子导图文章上下文：首次构建后把目录、分页导航和通读章节保存到插件私有 `cache/article-context-cache.json`，同时在会话内缓存已解析文档；再次打开时若全部依赖 `.mindmap` 的 `mtime + size` 未变化，会在编辑器首帧前同步命中，不再重复父子导图遍历。真实文档编辑、外部修改、删除或重命名会自动失效相关缓存；纯阅读、章节定位和返回目录只改变内存视图状态，不再把临时状态写回 `.mindmap`，因此无内容变化的目录往返不会制造 `modify` 并误删缓存。正文 MISS 时先挂载当前目标前后各约 5 KB 的真实章节 DOM，缓存 HIT 时首窗预算约 32 KB；目标语义位置稳定后，控制器会自动按动画帧向后、再向前补载剩余章节，每帧最多扩展 4 个约 5 KB 分块，并同步刷新缩略导航/滚动高度，所以不需要先手动滚到片段边缘。用户主动接近顶部或底部时仍保留原有约 5 KB 的边缘扩展兜底；向上补载会补偿新增高度，避免把当前段落顶走。首次进入正文、从目录跳向章节或切换文章时，会先显示一块固定范围的轻量骨架，让浏览器完成一帧绘制后再挂载真实窗口；骨架不覆盖已有正文、不创建章节占位，也不参与滚动高度。边缘扩展只在“加载前文/后文”按钮显示反馈：按钮文字始终双轴居中，加载时仅保留原有的按钮内部流光，不再运行额外的圆角边框动画；新增章节短暂淡入。目录点击会先确保目标章节进入窗口，再按精确节点 ID 恢复 `ReadingLocation`；位置采集只识别文章标题和真实章节，不把整页容器误判为根章节。过渡期间的位置会暂存到真实 DOM 挂载后执行，同一文件的目录项也不会重新打开文件。每次显式跳转使用可取消的独占事务，旧定时器和动画帧不能在新目标到位后再次滚动；图片、表格、代码或字体晚到造成布局变化时，会在短时稳定窗口内重新校准同一目标，用户滚轮、触摸、指针或键盘翻页会立即接管。系统启用“减少动态效果”时直接渲染而不等待动画。文章族上下文未准备完成时只显示与落地目标一致的局部骨架：配置为目录就直接显示目录骨架，不先闪出原始正文；目录与正文双向切换都使用同一过渡，返回目录从顶部进入。跨文件目录点击会在新文件视图创建前预排队精确节点，使首个真实窗口直接采用目标章节层级和标题，不先生成父章节编号再二次修正。显式章节或父级目标始终高于“显示目录”配置，即使文章族上下文尚未返回也会直接进入正文；切换物理文件时会取消上一文件的滚动事务。返回父导图若保存的父节点 ID 已失效，会按当前子导图路径在父导图中反查挂载节点。单次已挂载窗口仍通过 `WeakMap` 复用内容块规范化结果；文章编号、折叠、缩略导航、图片、表格、代码和行内编辑保持原有能力。
- 纯文字编辑提交只更新当前内容和必要的布局测量；延迟文章上下文刷新若只改变跨文件阅读快照，也不会重建当前页面。结构变化、目录层级或分页导航变化等仍走完整渲染，以保持模型、撤销和跨模式一致性。
- 插件内所有页面切换都有统一反馈：导图、大纲、文章、通读和题库模式切换、父子导图跳转、创建/提取子导图及合并回主导图会先显示带中文说明的过渡层，再执行大文件克隆、序列化和渲染。合并与提取会按“准备内容 → 更新主导图 → 打开目标页面”更新状态；目标页挂载后短暂淡入。页面切换失败会退出遮罩并提示错误。系统启用“减少动态效果”时保留状态文字但关闭动画。
- 跨文件章节点击与返回父导图会把精确节点 ID 保留到文章上下文完成。上下文刷新恢复位置时，本次显式目标绝对优先于骨架期间捕获的位置和历史跨文件阅读记录。生成目录本身是终止落地页：目录已激活时不会恢复任何章节位置，也不会因刚离开的子文件阅读记录再次自动进入子导图。调试模式会记录 `set-options-restore-choice.articleDirectoryActive`，可核对目录状态以及请求、捕获、历史和最终选择的节点。

### 界面与设置持久化性能

- 插件设置、阅读位置、设置分类展开状态和文章锁状态的连续变化会合并为最新快照并严格串行写入，避免快速操作时并发覆盖或频繁刷新 `data.json`；等待保存的调用仍会在对应版本真正落盘后完成。
- 文件浏览器筛选只响应文件浏览器中新加入的子树或 `data-path` 变化；文章重绘、弹窗和普通文件保存不会触发全树扫描。布局初始化或筛选设置语义变化时执行一次完整刷新，日常展开目录、创建和重命名文件只处理受影响的局部 DOM；每轮仍只解析一次后缀和文件夹规则。

### 节点与内容

- 有序混合内容块：文字、图片、表格和代码可通过独立手柄在节点内排序或跨节点移动；右键只删除鼠标所在块。
- 文章编辑工具栏可显式选择“作为块移动”或“作为节点移动”：当前块追加到目标节点末尾，当前节点则完整插入到目标节点之后。
- 富文本：加粗、斜体、下划线、删除线和文字颜色。
- 任务、标签、备注、链接、图标、表格和代码块；代码块在导图、大纲、文章和通读中共用同一渲染链路，行号与语法高亮代码保持逐行对齐，导图节点会随代码展开/折叠重新计算高度。
- 文章和通读中的表格默认铺满当前正文页面，历史列宽按比例自动适配窗口；拖动分隔线时相邻两列反向调整、总宽度不变，长内容在单元格内换行且不显示横向滚动条。释放拖动只保存列宽，不重建整篇文章，因此不会跳回目录或改变当前阅读段落。
- 节点内容编辑器使用有序内容块作为权威数据；删除表格块或代码块后会同步清理旧版兼容字段，保存并重开不会恢复已删除内容。删除或移走最后一个文字、图片、表格或代码块后，节点本身仍保留为空节点，不再因内容为空而自动删除；只有显式执行“删除节点”才移除树结构。导图中的空节点继续保持可点击的最小高度，文章行内编辑清空后也至少保留一行编辑高度。
- 文章行内编辑中，Enter 保存当前内容，Shift+Enter 插入换行；文章编号继承所在标题或正文的字体、字号和行高。中心节点的文章编号方式设为“关闭”时，当前物理导图内的章节、末端自动序号和子文章页标题编号全部隐藏，目录与结构层级仍保留；普通节点的“关闭”仍只跳过该节点。带圈编号在文章与通读中统一用正文数字和 CSS 圆环绘制，不再依赖系统的带圈字符字体，因此字重、尺寸和首行基线保持一致。文章编号固定为八级，第 8 级以下的更深结构继续保留标题层级，但不再循环回到 `A.` / `（A）`；同级字母编号超过 Z 后使用 AA、AB。
- 末端正文标识、样式、颜色和对齐方式可分别在插件设置与当前页面“文章样式”中配置；页面设置优先。对齐独立于标识开关，可选择顶格或自动缩进至上级标题下。
- 末端正文达到设置的兄弟节点阈值时，可选择转为“上级标题的下一级文章序号”或“带圈数字”。文章、通读和 HTML 导出会对全部带圈序号统一使用正文数字与 CSS 圆环，避免 Windows 字体回退造成 `①–㊿` 偏小、偏细或上下错位；在“自动（与上级标题对齐）”下，带圈编号正文与普通圆点正文保持同一首字起点；圆圈会略向编号区内收，并与正文保留清晰间距，避免出现“①正文”粘连。进入快速编辑时只按编辑框已有的顶部内边距下移圆圈，正文输入框、正文起点和水平缩进均保持不变。Markdown 与 Word 等无 CSS 输出仍在第 1–50 项使用原生 `①–㊿`，第 51 项以后使用可读回退。60、70 以及更多同级节点都可继续编号，且带圈样式也可用于第 8 级标题下面的更深末端正文。默认阈值为 4（3 个节点仍显示标识）。
- 完整节点编辑器中 Enter 保存并关闭，Shift+Enter 插入换行；输入法候选确认不会触发保存。
- 单节点和多节点复制、粘贴、删除及拖放。
- 撤销、重做、只读锁和自动保存。
- AI 助手：支持问答、经预览确认的 AI 节点重整、按范围顺序识别全部图片，以及完全离线的本地文字替换；范围可选当前页面或右键节点子树。

### 父子导图

节点可以关联独立 `.mindmap` 文件。子导图保存父文件路径、父节点 ID 和父标题，父导图保存子文件引用，从而支持：

- 从节点创建或提取子导图。
- 在父导图和子导图之间导航；导图模式的子导图左上角固定显示 `← 父导图 › 当前导图`。旧文件若缺少 `navigation.parentPath`，插件会从搜索索引中按父节点 `submap.path` 反向确认挂载关系并在运行态恢复该导航。
- 父文件或子文件重命名后的引用维护。
- 将子导图内容合并回父导图。
- 跨父子导图的文章目录与全局搜索；文章/通读右下角加载进度可在“视图与阅读”中按需开启，默认关闭。

### 图片与图床

导图或大纲中粘贴外部图片时，以粘贴瞬间的当前选中节点为唯一目标；“编辑节点内容”弹窗可通过“+ 粘贴图片”、图片块内按钮或 `Ctrl/Cmd+V` 直接插入剪贴板图片。


- 粘贴或选择本地图片后写入当前导图附近的资源目录。图片块可设置为“与相邻图片同行”或“独占一行”；导图、文章、通读和大纲会把连续同行图片放进同一个横向换行容器，小尺寸图片可以真正并排，不再各自占满一行。
- 支持多个 HTTP(S) 图床端点、JSON 请求头、`multipart/form-data` 或原始二进制请求体，并可为图床设置图片加载优先级。上传与删除请求共用同一份当前请求头，修改 Token 后不会留下过期的删除鉴权。上传前会计算图片二进制的 SHA-256；相同图片再次上传到同一图床时复用缓存地址，不重复发送，相同图片上传到不同图床仍分别执行一次。
- 新增图床默认使用 Zipline；预设列表保留 Zipline、ImgBB、Freeimage.host 和自定义。Zipline 上传响应保存文件 ID，删除最后引用时调用 `DELETE /api/user/files/{id}`；历史图片缺少 ID 时会通过当前 Token 查询文件列表补回 ID。ImgBB 保存上传响应中的唯一删除链接；Freeimage.host 的公开 API 只提供上传，插件不会假设存在匿名删除 API。
- 可配置响应字段路径，并兼容常见 `data.url`、`result.url` 等结构；粘贴或截图图片默认在本地保留 1 分钟，可设置 0–120 分钟，期间可直接进行 AI 识图；到期或下次打开导图发现已到期时自动上传并保留可达图床 URL。
- 导入图片的自动上传任务会跟随导图文件重命名继续执行；在导图画布空白处右键可选择“上传当前页面所有图片”，一次选择图床后补传当前物理页面中尚未覆盖这些图床的图片。
- 图片所有远程镜像与本地副本均加载失败时，导图、文章、通读和大纲会在原位置列出候选地址并提供“复制地址”，无需进入节点编辑器排查。
- 从系统剪贴板粘贴图片时会在异步保存前锁定当前节点和内容块位置；保存期间切换选区不会改变插入目标，原节点已删除时也不会回退到根节点或其他节点。
- 重新打开含多张待上传图片的导图时，自动上传按文件合并成批次，只显示汇总通知，并以节点 ID 与图片块 ID 将结果合并到最新文档，禁止旧快照整文件回写。
- 远程镜像与本地源并存；节点渲染和点击放大图片会先尝试优先级最高的可用图床地址，失败后再尝试下一个；仅在所有选定图床上传成功且确认没有其他引用时，才允许删除本地文件。图片块被删除后，默认启用“最后引用删除时同步清理图床”；确认全部 `.mindmap` 已无同一 SHA-256/远程 URL 引用后，远程删除先进入 1 分钟持久化安全队列。期间撤销恢复图片会在到期复查时自动取消删除；Obsidian 重启后仍会恢复未到期任务。API 连通性上传的测试图片也会在 1 分钟后自动清理。上传与删除共用当前请求头；Freeimage.host 等无公开删除接口的服务会安全保留远程文件并提示。
- 文件名、扩展名、MIME、请求头和返回 URL 经过独立工具层校验。
- 未启用任何有效图床时，图片右键菜单隐藏“上传到图床”；启用图床后才显示。图片右键可运行 AI 视觉识图或本机 Tesseract OCR；AI 识图可跟随全局接口或单独指定视觉模型，模型角色标记等无效输出会在预览前清理。识别后可选择直接后台确认、5/10/15 秒后自动确认或手动确认；替换会保留原位置，并安全删除不再被引用的本地图片。
- “截图与识别”是位于“AI 助手”之后的独立设置分类。普通截图与截图并识别分别使用 `Ctrl/Cmd+Shift+S` 和 `Ctrl/Cmd+Shift+R`，可独立录制；节点右键和顶部工具栏均提供两种入口。Windows 截图源覆盖完整虚拟桌面，编辑器可在“全部屏幕”和各块显示器之间切换，按原始像素比例显示与导出，不再因 DPI 或窗口宽高比拉伸。标注支持矩形、圆角矩形、椭圆、填充、颜色与粗细样式，箭头可切换为直线；文字使用兼容中文输入法的画布内输入框；显示器名称由编辑器本地生成避免乱码。截图编辑器默认以当前屏幕完整范围作为选区；普通截图显示完整标注与输出工具栏，保持选区常驻，双击选区后复制并插入；截图并识别的完整工具栏 DOM 仍保留，但完全透明且不接收鼠标事件；倒计时仅显示整数 `3、2、1`。鼠标悬停选区边框、拖动条或缩放手柄时暂停，离开边框或重新框选后从 3 秒重新开始，Esc 可从 iframe 或宿主窗口退出。

### AI 助手

- 内置 OpenAI、DeepSeek、硅基流动、FreeLLMAPI 和自定义 OpenAI 兼容接口配置。
- 每个接口可持久化选择自动、开启或关闭思考模式；可从兼容服务的 `/models` 目录读取并缓存模型列表，首次仍使用预设模型时会自动切换到获取列表的首项。
- AI 助手弹窗提供与当前接口配置同步的“深度思考”开关，切换后立即保存并用于后续请求。
- 硅基流动预设提供 DeepSeek V4 Flash、DeepSeek V4 Pro、DeepSeek OCR、GLM-4.5V 和 GLM-5.2 模型建议；FreeLLMAPI 默认使用 `auto` 路由。
- 每个接口卡片提供“检测接口”按钮，以最小提示词验证地址、鉴权、模型和响应格式，不发送导图正文。
- 工具栏按钮与 `Ctrl/Cmd+Shift+A` 默认询问当前页面。
- 节点右键可仅发送该节点及全部子节点；文章模式最上方主标题或页面空白处右键均使用整页范围。
- 发送前显示节点数、字符数和 UTF-8 大小；超过设置上限时禁止请求，不静默截断。
- AI 窗口默认进入“AI 整理并重新生成”，问答与整理会流式显示模型思考和生成内容；识图按节点树顺序处理当前页面或右键节点子树中的全部图片，并可使用独立视觉接口避免纯文本默认模型拒绝图片请求。
- 询问问题与 AI 编辑要求分别保存草稿；切换到 AI 编辑时自动填入整理层级、合并重复节点的默认要求。
- AI 编辑先生成完整 Markdown 提案并显示节点数量和内容预览，用户确认后才替换页面或节点子树，并可撤销。
- 本地替换不联网，可在相同范围内替换节点文字、备注和表格，同时避开链接、代码、图片地址和子导图路径。
- 询问窗口显示“转换 Markdown、上传上下文、模型处理、接收结果”处理轨迹并渲染 Markdown 回答。

详细配置、安全边界和操作方式见 [docs/AI_ASSISTANT.zh-CN.md](docs/AI_ASSISTANT.zh-CN.md) 与 [docs/IMAGE_RECOGNITION_SCREENSHOT.zh-CN.md](docs/IMAGE_RECOGNITION_SCREENSHOT.zh-CN.md)。

### 搜索、导入与导出

- 本地增量索引与全局搜索、正则匹配和替换；在 MindMap Studio 视图中按 `Ctrl/Cmd+F` 会直接打开当前父子导图族搜索，不依赖 Obsidian 的“搜索当前文件”快捷键绑定。导图族刷新优先复用已按 `mtime + size` 校验的新鲜索引，只有文件新增或变化时才重新读取对应 `.mindmap`，避免每次打开搜索都顺序重读整条父链。点击搜索结果时关闭 selection 恢复，并且只调用一次 Obsidian 公开的 `Modal.close()`：不再模拟 `.modal-bg` 点击，不修改或删除 `.modal-container` / `.modal-bg`，也不等待 `onClose()` Promise。关闭请求发出后让宿主获得两个绘制帧完成 history/focus bookkeeping，再开始目标文件与节点导航；调试模式会记录 `result-close-request`、`modal-on-close` 和 `result-navigation-start`，用于确认真实桌面端的关闭顺序。 全局搜索入口额外保持单实例：若同一快捷键同时被插件捕获层与 Obsidian 热键链处理，第二次触发会被去重，不会叠加第二个搜索遮罩；当前导图族搜索保持独立。搜索跳转到文章位置后，用户直接单击标题或正文进入行内编辑时会立即接管并终止仍存活的语义定位/窗口扩展事务，避免迟到的恢复重绘替换编辑器；指针入口只在最初 120 ms 保护宿主焦点交接，并保留单击位置光标。右键菜单“编辑当前内容/添加正文”仍保留独立的菜单关闭焦点保护；“全部替换”始终覆盖当前搜索范围内的全部匹配，不受界面显示条数限制。
- Markdown、缩进文本、剪贴板分支和新版 XMind 导入；XMind 主题图片会从归档 `resources/` 中提取到当前导图资源目录；跨画布嵌套时，同名挂载主题会继承被链接画布根主题上的图片、公式和备注，公式继续保留为可编辑 LaTeX 内容块；桌面 Markdown 导入同样会复制可读取图片、改写节点引用，并按现有设置安排图床自动上传。
- Markdown、HTML、SVG 及文章内容导出；文档导出始终按通读全文合并，目录层级跟随文章目录设置，子导图目录项会跳到对应章节；Markdown 使用普通标题链接，Word 生成带内部书签的 .docx，PDF 在桌面端直接保存到所选位置。
- Markdown 阅读模式中的静态导图预览。

## 安装

### 手动安装

1. 创建目录：

   ```text
   <你的仓库>/.obsidian/plugins/mindmap-studio/
   ```

2. 将以下三个文件复制到该目录：

   ```text
   main.js
   manifest.json
   styles.css
   ```

3. 重启 Obsidian，或重新加载插件列表。
4. 在“设置 → 第三方插件”中启用 **MindMap Studio**。
5. MindMap Studio 设置页的一级分类默认全部收起，并记住用户上次展开的分类列表；顶部搜索会临时展开匹配分类，清空搜索后恢复原来的展开状态。

### 从源码构建

```bash
npm ci
npm run verify
```

构建完成后，仓库根目录的 `main.js`、`manifest.json` 和 `styles.css` 即为安装文件。生产构建不会内嵌 source map；若合并时 `main.js` 冲突，应先合并 `src/` 源码，再执行 `npm run build` 重新生成它。

## 基本使用

### 新建导图

通过左侧功能区的脑图按钮、命令面板中的“新建思维导图”，或文件夹右键菜单创建 `.mindmap` 文件。

### 切换视图

使用工具栏或命令面板切换导图、大纲、文章和通读模式。四种模式共享同一个“当前阅读节点”：

- 在导图中点击节点后切换模式，目标模式会聚焦同一节点。
- 从文章切到导图进行修改再返回文章时，会直接定位导图当前节点；程序化恢复期间不会误触发连续“加载前文”。
- 在大纲、文章或通读中滚动到某一段后切换模式，会按视口锚点定位对应节点。
- 进度按文章族顶层文件持久化，关闭视图、重启 Obsidian 或重新打开文件后继续恢复。
- 通读位置属于子导图时，切换到导图、大纲或文章会自动打开对应子导图。
- 节点被删除时依次回退到父节点；子导图不存在时回退到父导图的挂载节点。

导图、文章和通读可作为下次启动模式。大纲只在当前会话同步，不会成为插件重启后的默认模式。设置中的“进入文章模式”可选择默认锁定、沿用进入前状态或记住文章模式自己上次的锁定/编辑状态；“记住”不会被导图、大纲或其他模式的锁状态覆盖。

### 创建子导图

在节点操作中选择创建或提取子导图。文件默认保存到：

```text
父导图所在目录 / MindMap Assets / 父导图文件名 / 子导图.mindmap
```

资源目录名称可在插件设置中修改。

### 配置图床

插件设置的“管理配置”分类提供“导出配置”“导入配置”和“恢复初始配置”：可将全局设置（包括图床和 AI 接口）保存为 JSON 并在另一台设备恢复；导入或恢复只影响插件设置，不会修改任何 `.mindmap` 文件。

同一分类提供“调试模式”。启用后，插件从本次启动会话开始在内存中记录用户操作和导航内部状态，包括点击、按键、滚动、文件/视图切换、目录/父级导航、文章窗口与语义定位，以及运行异常；不会记录文章正文、输入框内容、图床密钥或 AI 请求正文。复现问题后，在命令面板执行“复制 MindMap Studio 调试记录”，即可把结构化 JSONL 复制到剪贴板。日志有数量上限，关闭调试模式或重启插件会清空。

截图与截图并识别快捷键分别使用按键录制：点击对应输入框后按下单键，或包含 Ctrl、Shift、Alt 的两键、三键组合，即可独立保存。

图片识图转文字后，所在节点默认左对齐。包含多个文字块或图片块的节点可直接双击目标文字块进行行内编辑；双击图片块会打开并高亮对应的完整编辑卡片。快速编辑与“编辑节点内容”现在共用加粗、斜体、下划线快捷键配置，选中文字后可在两处使用相同按键组合；完整编辑器会去重浏览器随后产生的格式输入事件，避免 `Ctrl/Cmd+B` 加粗后立即被反向切换。图片放大预览采用较收敛的 `86vw × 82vh` 上限，避免覆盖几乎整个 Obsidian 窗口。

空节点截图后再进行 AI/OCR 识图时，识别结果会填入原有的第一个空文字块，不会额外留下空白文字块。

在插件设置中添加图床配置，并填写：

- 上传端点，必须是 HTTP 或 HTTPS URL。
- 请求方法：`POST` 或 `PUT`。
- 请求体：`multipart/form-data` 或原始二进制。
- 文件字段名。
- JSON 请求头。
- 返回图片 URL 的字段路径。
- 可选的删除令牌字段、删除 API、删除方法、请求头和请求体模板；删除模板可使用当前 URL、SHA-256 与服务端删除令牌。
- 加载优先级：数值越小越优先，用于节点图片渲染和点击放大时的故障转移顺序。

建议先使用“测试连接”验证认证、请求格式和响应解析，再启用自动上传。

## 数据与隐私

- `.mindmap` 文件是唯一事实来源。
- 搜索索引是可重建缓存，不替代原始文件。
- 插件默认在本地读写 Obsidian 仓库。
- 只有配置并触发图床上传时，图片数据才会发送到用户指定的服务。
- 只有用户在 AI 窗口点击发送后，所选范围的 Markdown 才会发送到用户指定的 AI 服务。
- 图床和 AI 凭据保存在 Obsidian 插件设置数据中；请勿把包含真实令牌的设置文件提交到 Git。

数据结构详见 [docs/DATA_MODEL.md](docs/DATA_MODEL.md)。
