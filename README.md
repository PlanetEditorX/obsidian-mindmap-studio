# MindMap Studio for Obsidian

## 1.6.0 同级节点自由拖动排序

导图模式现在支持按落点决定拖拽结果：

- 拖到目标节点上方：插入目标之前；
- 拖到目标节点下方：插入目标之后；
- 拖到目标节点中间：成为目标的子节点。

拖动过程中会显示插入线或子节点高亮。排序会同步到大纲和文章模式，并支持撤销、重做和自动保存。现有 `.mindmap` 文件无需迁移。

## 1.5.0 子导图整块点击、文字对齐和节点尺寸

导图模式中的子导图节点现在把整个节点作为进入范围。鼠标点击节点标题或标题附近的空白区域都会直接进入子导图，不再需要精确命中文字。右键节点仍可打开编辑菜单；键盘聚焦后按 Enter 或空格也可以进入。

### 节点文字对齐

可以在两处控制：

- `设置 → MindMap Studio → 默认节点文字对齐`：统一控制所有未单独设置的节点；
- `编辑节点内容 → 文字对齐`：让当前节点跟随全局、左对齐、居中或右对齐。

对齐方式会作用于普通文字、富文本和子导图标题，并同步到 SVG 导出。

### 节点宽度与高度

默认状态下，节点右下角只显示折叠/展开及下级数量按钮。按住 `Ctrl`（macOS 为 `Cmd`）并将鼠标移到节点上时，数量按钮会暂时隐藏，并在同一位置显示小型尺寸控制点：

- 向左右拖动调整宽度；
- 向上下拖动调整最小高度；
- 双击控制点恢复自动大小；
- 右键节点也可以选择“恢复节点自动大小”。

松开 `Ctrl/Cmd` 或移开鼠标后，控制点立即恢复为右下角的下级数量按钮。普通点击或选中节点不会显示尺寸控制点。`Shift` 始终保留给节点多选和框选。

编辑节点窗口还提供精确数值：

```text
节点宽度：100–900 px
节点最小高度：36–600 px
```

文字会根据节点宽度自动换行。宽度足够大时保持一行；缩小宽度后会自动排成多行，布局和连接线会重新计算。高度属于“最小高度”，内容较多时节点仍会自动增高，不会裁掉文字。

现有 `.mindmap` 文件不需要转换。

MindMap Studio 是一个本地优先、可重新打开继续编辑的 Obsidian 思维导图插件。脑图保存为独立的 `.mindmap` JSON 文件，不会在第二次打开时变成 Markdown 源码或静态图片。

## 1.4.6 子导图节点入口合并

导图模式中，关联子导图的节点不再在标题下方显示一个重复的同名“进入子导图”按钮。节点第一段标题文字本身就是子导图入口，末尾使用轻量箭头提示：

```text
李白 ↗
```

- 点击子导图节点的文字或空白区域都会直接进入对应子导图；
- 右键节点可继续编辑、调整样式或执行其他操作；
- 纯图片节点没有标题时，节点右上角会显示一个小型箭头入口；
- 大纲和文章模式继续使用标题文字超链接。

已有 `.mindmap` 文件不需要迁移。

## 1.4.1 文章编号、全局模式和父子导图目录修复

本版修复 1.4.0 中文章编号未覆盖独立子导图的问题。文章层级现在会跨 `.mindmap` 文件继续计算：顶层父导图中的子导图节点可显示为“第一章”，进入该子导图后，它的第一个有下级节点会继续显示为“第一节”，不会重新从“第一章”开始。

例如：

```text
古诗.mindmap
└── 唐诗（子导图）       → 第一章 唐诗
    └── 李白（有子级）   → 第一节 李白
        └── 静夜思       → 末端正文，不编号
```

子导图节点即使没有本地 `children`，只要保存了 `submap.path`，也会被识别为文章标题。原来的“只有有下级的节点才编号”和“文章模式不自动编号”规则继续有效。

### 模式改为全局记忆

点击工具栏中的“导图 / 大纲 / 文章”后，选择会保存为插件的全局当前模式。之后打开父导图、子导图或其他 `.mindmap` 文件，都会继续使用同一种模式。每个文件不再各自记忆不同模式；只读锁仍按文件保存。

### 子导图文字链接

在大纲和文章模式中，子导图节点不再显示单独的“进入子导图”按钮。节点标题本身会显示为超链接样式，点击文字即可进入对应子导图，并继续保持当前全局模式。完整编辑仍可使用节点旁的铅笔按钮。

### 顶层文章目录页

当当前文件是最上层父导图并且包含子导图时，文章模式会在正文前生成独立目录页。目录会递归读取全部后代子导图，显示跨文件的章、节等编号；点击目录项可打开对应导图并定位到具体节点。子导图页面不会重复生成整棵导图族目录。

已有父子导图不需要重新创建，也不需要重建搜索索引。

## 1.4.0 导图、大纲与文章三种同步模式

同一个 `.mindmap` 文件现在可以使用三种表现方式，三者共用同一棵节点树，不会复制数据：

- **导图模式**：原来的可缩放、可拖动思维导图画布；
- **大纲模式**：按照节点层级显示缩进大纲；
- **文章模式**：根据层级生成目录、章节标题和正文。

在任意模式修改节点，其他模式会立即同步。例如在文章模式把“唐诗”改成“唐代诗歌”，切回导图和大纲后会看到同样的内容。只读状态会写入 `.mindmap` 文件；显示模式从 1.4.1 起改为全局记忆，打开任意父导图或子导图都会继续使用最近选择的模式。

### 模式切换与只读锁

工具栏左侧新增模式切换按钮和锁按钮：

```text
导图 ｜ 大纲 ｜ 文章 ｜ 🔓/🔒
```

锁定后只能查看、搜索、打开链接、进入子导图、缩放和平移。新增、删除、拖拽、粘贴、样式修改和节点编辑都会停用。只读状态下仍可临时展开或收起分支，但不会把折叠状态写回文件。

命令面板新增：

```text
切换到导图模式
切换到大纲模式
切换到文章模式
切换导图只读 / 编辑模式
```

### 大纲模式

大纲模式会展开显示所有层级，包括导图中已折叠的节点。可以：

- 直接点击节点文字进行编辑；
- 双击打开完整节点编辑器；
- 添加子节点、删除节点；
- 查看任务状态、备注，并点击子导图标题文字直接进入；
- 点击结果定位到相同节点。

### 文章模式编号：自动、关闭与手动层级

文章模式默认使用**自动编号**。自动模式按照节点在文章结构中的层级生成编号；有子节点或关联子导图的节点作为标题，普通末端节点作为正文。默认层级为：

```text
1 级：第一章
2 级：第一节
3 级：一、
4 级：（一）
5 级：1.
6 级：（1）
7 级：A.
8 级：（A）
```

在节点的完整编辑窗口中，可以设置“文章编号方式”：

- **自动**：沿用树结构和父标题层级，这是默认行为。
- **关闭**：当前节点不显示编号，也不占用该层级的后续序号，适合前言、摘要、注释和附录。
- **手动层级（自定义最高层级）**：为当前节点所在子树指定最高可见文章层级（1–8 级）。在中心节点设置时，一级子节点直接使用所选层级；在普通标题节点设置时，该节点使用所选层级，后代继续向下推导。该选项只改变层级，不会把孤立末端节点强制变成标题。

同一组子节点中，只要存在有下级内容或关联子导图的自然标题，其余同级末端节点也按同级标题处理。因此“词义”即使自身没有子节点，也不会丢失第一个序号。编号按文章层级分别计数；同一父节点下混用“一、”与“1.”时，两种格式各自从 1 开始，不会互相挤占序号。

“文章编号方式”和“最高文章层级”既可在中心节点完整编辑窗口中设置，也可在工具栏的**当前脑图外观**中设置，两处修改的是同一份中心节点配置。

#### 配置成“一、 / （一）”

在中心节点或“当前脑图外观”中选择：

```text
文章编号方式：手动层级（自定义最高层级）
最高文章层级：3 级 · 一、示例
```

导图结构保持为：

```text
成语辨析（中心节点）
├── 相得益彰
│   ├── 词义：……
│   ├── 易混淆成语
│   │   └── 相辅相成：……
│   └── 区分
│       └── 具体解释……
└── 方兴未艾
    ├── 词义：……
    ├── 易混淆成语
    └── 区分
```

文章会生成：

```text
一、相得益彰
（一）词义：两个人或两种事物互相配合，双方的长处和作用更能显示出来。
（二）易混淆成语
    相辅相成：两种事物互相配合，互相促成，缺一不可。
（三）区分
    相得益彰指两者互相配合能达到更好的效果，重在效果好。

二、方兴未艾
（一）词义：事物正在兴起、发展，一时不会终止。
（二）易混淆成语
（三）区分
```

不需要逐个把“词义”“易混淆成语”“区分”设置为手动层级。它们会根据同级标题结构自动使用下一层编号；解释内容仍作为正文。

#### 配置成“1. / （1）”

在中心节点或“当前脑图外观”中把最高文章层级改为 5 级：

```text
文章编号方式：手动层级（自定义最高层级）
最高文章层级：5 级 · 1.示例
```

即可得到：

```text
1.相得益彰
（1）词义：两个人或两种事物互相配合，双方的长处和作用更能显示出来。
（2）易混淆成语
（3）区分

2.方兴未艾
（1）词义：事物正在兴起、发展，一时不会终止。
（2）易混淆成语
（3）区分
```

带顿号、句点或右括号的编号会紧贴标题；“第一章”“第一节”与标题之间保留空格。手动最高层级同时作用于文章正文、文章目录、通读模式、跨子导图层级和 HTML/Word/PDF 导出。旧文件中的 `skipArticleNumbering: true` 会自动兼容为“关闭”。

“文章目录最大层级”按目录的相对树结构计算，与编号样式分离。例如最高编号层级设为 5 时，一级标题虽然显示为 `1.`，在目录中仍属于第 1 层，不会因为默认只显示 3 层而被过滤。

插件设置中的“文章目录最大层级”是全局默认值。在“当前脑图外观 → 文章编号与目录”中，目录最大层级默认选择“跟随插件设置”；手动选择 1–8 层后，该 `.mindmap` 文件会优先使用自己的设置，并同时作用于文章模式目录和通读模式全书目录。改回“跟随插件设置”即可删除当前脑图覆盖值。

文章模式保持原有目录交互：只有最上层脑图存在子导图时才提供目录页，工具栏可在“纯目录页”和“原始文章”之间切换；原始文章正文顶部不会自动插入目录。当前脑图的目录最大层级覆盖仍会作用于该目录页和通读模式全书目录。

子导图文章页底部的上一篇/下一篇按**同层物理页面**切换，不再沿递归目录进入当前页面内部的子节点。例如进入“第一章 世界”后，下一篇会直接打开兄弟页面“第二章 中国”，不会跳到本页的“第一节 世界历史”。如果当前物理页面本身位于节级，则只在同一父章节下的节级兄弟页面间切换。子导图文章页顶部会组合父目录计算出的编号与当前根标题，显示为“第一章 世界”，而不是只显示“世界”。

#### 模式切换保留导图缩放

从导图模式切换到大纲、文章或通读模式时，当前缩放比例和平移位置会写入文档视图状态。再次返回导图模式会恢复原视口，不再自动执行“适应画布”。只有首次打开且没有保存过视口、并启用了自动适应时，才会执行一次自适应。

### 显示模式设置与一键还原

在插件设置的“显示模式”区域，可以隐藏不需要的模式。例如仅启用“导图”和“文章”，工具栏中将不再显示“大纲”。至少会保留一种模式，并且可以设置当前全局显示模式；工具栏切换也会同步更新这一设置。

设置页底部新增“一键还原所有插件设置”。它会恢复主题、显示模式、资源目录、图床、搜索和编辑选项，但不会删除或修改任何 `.mindmap` 文件。

## 1.3.1 父导图与子导图递归搜索修复

搜索现在会识别真实的父子导图关系，而不是只把每个 `.mindmap` 文件当作互不相关的文件。

例如：

```text
古诗.mindmap
└── 唐诗（子导图）
    └── 李白
```

在 `古诗.mindmap` 中按 `Ctrl/Cmd + F` 搜索“李白”，插件会递归读取“唐诗”子导图并返回对应节点。点击结果后会打开 `唐诗.mindmap`、展开相关分支并定位到“李白”。结果层级会显示为：

```text
古诗 › 唐诗 › 李白
```

已有子导图**不需要重新创建**。打开当前导图搜索时，插件会即时刷新当前父导图及其全部后代子导图；只要父节点仍保存 `submap.path`，或者子导图仍保存 `navigation.parentPath`，旧文件就可以自动识别。即使从“唐诗”子导图发起搜索，也会先向上找到“古诗”，再搜索完整导图树。

两个搜索入口分别是：

```text
Ctrl/Cmd + F          当前导图及递归关联的全部子导图
Ctrl/Cmd + Shift + F  整个仓库中的全部思维导图
```

当前导图族搜索会按需更新相关文件，不要求先手动重建整个仓库索引。全局搜索仍使用本地增量索引库，并支持用多个层级关键词搜索，例如“古诗 唐诗 李白”。

## 1.3.0 全局搜索与本地索引库

新增跨整个 Obsidian 仓库的思维导图搜索。点击导图工具栏中的“全局搜索”按钮，或使用：

```text
Ctrl/Cmd + Shift + F
```

搜索范围包括所有 `.mindmap` 文件中的：

- 根节点、普通子节点和任意深度的后代节点；
- 已折叠但当前没有显示的分支；
- 每个独立子导图文件中的节点；
- 多段富文本、备注、标签和链接；
- 表格表头及单元格；
- 代码语言和代码内容；
- 子导图名称及路径；
- 图片替代文字和资源路径。

点击搜索结果后，插件会打开对应 `.mindmap` 文件，自动展开目标节点的祖先分支，并将目标节点居中选中。搜索结果会显示导图名称、文件路径、节点层级路径和命中的内容类型。

### 是否依赖数据库

插件不使用外部服务器或云数据库，而是在插件目录中维护一个本地增量索引文件：

```text
.obsidian/plugins/mindmap-studio/mindmap-search-index.json
```

它相当于只服务于思维导图搜索的本地索引库。启动时只读取发生变化的文件；之后监听 `.mindmap` 文件的新建、修改、重命名和删除并增量更新。正常搜索不会每次重新读取所有导图。

索引只保存可搜索文字、节点 ID、文件路径和层级信息，不保存图片二进制，也不会上传网络。可以在插件设置的“全局搜索索引”区域查看收录数量、调整结果上限或手动重建索引。

## 1.2.1 连线渐细修复

“从粗到细”现在按照当前导图实际可见的最深层级计算。即使导图只有两层或三层，一级分支仍使用“起始粗细”，最深一层会达到“末端最细宽度”，不会再因为固定按五层计算而看不出变化。

如果节点分支被折叠，渐细计算会以当前可见层级为准；展开更深分支后会自动重新计算。


## 为什么不再叫 MindMap Canvas

旧名称中的 Canvas 只是指可缩放、可平移的编辑区域，但容易与 Obsidian 自带 Canvas 功能混淆。从 0.9.0 起，插件正式更名为 **MindMap Studio**：

- 插件显示名称：`MindMap Studio`
- 插件 ID 和安装目录：`mindmap-studio`
- 脑图文件后缀：`.mindmap`（保持不变）
- 旧插件设置：首次启动新版时会尝试从 `mindmap-canvas/data.json` 自动迁移

升级后请关闭并移除旧的 `mindmap-canvas` 插件目录，避免两个插件同时注册 `.mindmap` 文件类型。

## 1.2.0 重点功能

### 多套主题模板

“当前脑图外观”窗口顶部新增主题选择区，内置 10 套独立设计的脑图主题：

- 经典靛蓝
- 深海蓝
- 森林绿
- 日落橙
- 薰衣草
- 糖果缤纷
- 纸张笔记
- 极简墨色
- 暗夜霓虹
- 薄荷清新

主题不是只替换背景，而是会一起应用：

- 画布背景和网格/点阵；
- 中心主题颜色和文字颜色；
- 普通节点背景、文字和边框；
- 一级分支循环配色；
- 字体和字号；
- 连线颜色、类型和粗细模式。

选择主题后，仍可以继续修改任意单项。当前脑图的主题和后续微调都会写入 `.mindmap` 文件，重新打开后保持不变。插件设置页也提供“默认主题”，用于之后新建的脑图。

### 连线从粗到细

连线新增两种粗细模式：

```text
统一粗细
从粗到细
```

“从粗到细”模式使用两个参数：

- **起始粗细**：中心主题到一级分支的线宽；
- **末端最细宽度**：深层节点连线的最小宽度。

插件会根据节点层级平滑递减线宽。例如设置起始 4.5 px、末端 1 px 后，一级分支最粗，二级、三级逐渐变细，深层分支保持在 1 px，不会无限变细。

起始粗细和末端最细宽度均支持 `0.05 px` 的精度，因此主题中的 `4.2 px`、`1.2 px` 等值可以直接应用，不会触发浏览器的“请输入有效值”提示。

彩色分支开启后，同一个一级分支下面的所有后代会沿用相同的连线和节点边框颜色。SVG 导出和 Markdown 静态预览也会保留主题及渐细连线。

旧用户升级后，原有全局配置默认继续使用统一粗细和彩色分支关闭，不会自动改变现有脑图外观。新建安装默认使用经典靛蓝主题和渐细连线。

## 1.1.0 重点功能

### 图床镜像自动故障转移

同一张图片上传到多个图床后，插件会把所有网址按优先级保存在图片块中。打开可编辑脑图并加载图片时：

```text
当前主地址加载失败或超过等待时间
→ 尝试下一个图床地址
→ 成功后立即显示备用图片
→ 将成功地址写成新的主地址
→ 自动保存 .mindmap 文件
```

例如镜像顺序为图床 A、图床 B、图床 C：

- A 失效时自动切换到 B；
- B 以后失效时继续尝试 C；
- 如果开启本地回退且本地副本仍存在，远程镜像全部失败后会使用本地图片；
- 原镜像地址不会从列表删除，便于恢复后手动切换或继续作为备用地址。

设置位置：

```text
Obsidian 设置 → 第三方插件 → MindMap Studio → 图片与图床
```

可设置：

- 是否启用远程图片自动故障转移；
- 单个镜像等待时间，范围 2–30 秒；
- 是否将本地副本作为最后回退。

故障转移在图片实际加载时触发。图床如果返回 HTTP 200 的占位图或错误图片，而不是加载错误，插件无法仅凭浏览器图片事件判断内容是否正确。

## 1.0.0 重点功能

### 可排序的文字与图片内容块

节点不再固定为“一个标题加一张图片”，而是由多个内容块组成。内容块可以上下移动：

- 纯文字
- 纯图片
- 图片 → 文字
- 文字 → 图片
- 文字 → 图片 → 文字
- 多张图片和多段文字任意穿插

编辑节点时，可以删除默认的“新节点”文字块。只要还保留一个有效图片块，节点就会作为纯图片节点保存。

每个文字块都支持局部富文本：选择任意字符后设置加粗、斜体、下划线或颜色，下方实时预览。不同文字块可以分别设置格式。

### 图片点击放大

在可编辑脑图中点击任意图片会打开大图预览：

- 鼠标滚轮缩放
- `+` / `−` 调整缩放
- `100%` 恢复原始比例
- 双击图片恢复 100%
- 大图可在预览窗口中滚动查看

### 本地图片资源

粘贴图片或点击“保存到仓库”时，图片默认保存到：

```text
当前脑图所在目录 / 设置的资源文件夹 /
```

例如：

```text
Projects/
├── Plan.mindmap
└── MindMap Assets/
    └── Plan-20260720-123456.png
```

资源文件夹可在插件设置中修改，默认是 `MindMap Assets`。

### 多图床、自动上传与安全删除

插件可以配置多个通用 HTTP 图床，每个图床分别设置：

- 名称和启用状态
- 上传 API 地址
- `POST` 或 `PUT`
- `multipart/form-data` 或原始二进制
- multipart 文件字段名
- 自定义请求头 JSON
- 返回图片地址字段，例如 `data.url`、`result.image`

每个图床都有“检测 API 连通性”按钮。检测会实际上传一张 1×1 透明 PNG，以验证鉴权、请求格式和返回网址解析，因此图床中可能留下一个很小的测试文件。

手动上传时会弹出图床选择窗口，可以选择一个或多个目标。第一项成功返回的网址作为节点当前显示地址，其余网址作为镜像保存在 `.mindmap` 文件中。

自动上传采用本地优先流程：

```text
粘贴图片
→ 先写入当前脑图目录的资源文件夹
→ 等待设定的延迟时间
→ 同时上传到选中的一个或多个图床
→ 全部成功后把节点引用替换为第一项远程网址
→ 先保存脑图
→ 确认本地图片未被其他脑图引用后再删除本地文件
```

只要任一目标失败，节点继续使用本地图片，本地文件不会删除。已经成功的图床网址仍会作为镜像记录，方便后续排查或重试。

设置位置：

```text
Obsidian 设置 → 第三方插件 → MindMap Studio → 图片与图床
```

可设置：

- 粘贴图片后自动上传开关
- 0–300 秒上传延迟
- 默认自动上传目标，可多选
- 全部成功后是否删除本地图片
- 多个图床配置

自定义请求头会保存在插件的 `data.json` 中。不要在共享仓库或不可信设备中保存敏感令牌。

## GitHub Actions 自动构建与发布

仓库包含两个工作流：

- `Build and Test`：提交到 `main`、Pull Request 或手动运行时执行 `npm ci`、测试、文档检查和构建，并上传可安装插件构建产物。
- `Create Release`：在 Actions 页面手动运行，选择 `patch`、`minor` 或 `major`。工作流会同步更新 `package.json`、`package-lock.json`、`manifest.json` 和 `versions.json`，构建插件，提交版本变更，创建 `vX.Y.Z` 标签，并发布安装 ZIP、源码 ZIP 和 SHA-256 校验文件。

首次使用前，请在仓库设置中确认：

```text
Settings → Actions → General → Workflow permissions
```

选择：

```text
Read and write permissions
```

同时建议启用：

```text
Allow GitHub Actions to create and approve pull requests
```

发布时进入：

```text
Actions → Create Release → Run workflow
```
