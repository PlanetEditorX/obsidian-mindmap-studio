## 2. 项目概览

MindMap Studio 是 Obsidian 的本地优先思维导图插件。插件以 `.mindmap` 文件保存结构化文档，并提供导图、大纲、文章和通读四种同步视图。

核心能力包括：

- 节点创建、编辑、排序、折叠、多选和拖放。
- 文本、富文本、备注、标签、任务、代码、表格、链接和图片内容块。
- 导图、大纲、文章和通读模式间的内容与阅读位置同步。
- 父子导图创建、提取、合并和双向导航。
- 全局搜索、Markdown/XMind/FreeMind 导入以及多格式导出。
- 本地图片保存、可选图床上传、多图床镜像和安全删除检查。
- 主题、布局、快捷键、只读锁定和嵌入预览。

## 4. 数据模型与当前边界

`.mindmap` 文档由根节点、子节点、显示设置和导航信息组成。详细字段见 `docs/DATA_MODEL.md`。

维护时必须遵守：

1. 所有读取入口统一经过模型解析和规范化。
2. 富内容修改后调用 `syncNodeContentFields()` 同步派生摘要字段。
3. 父子导图的 `parentPath`、`parentNodeId`、`parentTitle` 和节点 `submap` 引用必须成对维护。
4. 不兼容的数据变化必须提升版本，并提供独立、可审计的转换工具。
5. 运行时不继续累积字段、枚举、文件名或载荷名的永久别名。

当前 `.mindmap` 数据版本为 `10`。统一阅读位置保存在插件设置的 `readingLocations` 中，不写入业务文档。

## 5. 架构

### 5.1 主要模块

```text
src/
├── main.ts                  插件生命周期、文件服务、子导图和图床编排
├── view.ts                  Obsidian 视图适配
├── settings.ts              设置模型与设置页
├── core/                    数据模型、节点树和序列化
├── editor/                  编辑器、富文本、拖放、历史和工具栏
├── render/                  布局、碰撞与静态渲染
├── article/                 文章结构、显示模式规则与统一阅读位置
├── search/                  全局搜索
├── import/                  导入与导出
└── utils/                   无 Obsidian 依赖的确定性工具
```

### 5.2 依赖方向

```text
Obsidian 生命周期与 UI
        ↓
main.ts / view.ts / settings.ts
        ↓
领域编排与编辑器
        ↓
core / render / article / import / search
        ↓
utils 纯函数
```

`utils` 不得反向依赖 Obsidian、编辑器或插件实例。这样可以在 Node.js 中直接测试安全校验和格式转换。

### 5.3 统一阅读位置

`src/article/reading-location.ts` 使用语义位置代替单一滚动百分比：

```text
文章族顶层文件
  └─ 目标物理文件
       └─ 目标节点 → 父节点 → 祖先 → 根节点
  └─ 父导图挂载节点 → 祖先 → 根节点
```

每条记录同时保存目标节点内部比例和视口锚点比例。切换导图、大纲、文章或通读时，编辑器先解析最新节点树，再恢复到同一节点；目标位于子导图时，非通读模式由视图层打开对应物理文件。节点、子导图或路径发生变化时按保存的祖先链逐级回退。文件重命名事件会同步更新语义阅读位置中的文章族键、目标路径和父级回退路径。

`src/article/display-mode.ts` 将大纲定义为会话级模式：它会在当前已打开视图间同步，但不会写成下次启动模式。加载到 `outline` 时会解析到导图；导图不可见时回退到可见的文章或通读模式。

### 5.4 本次新增边界

#### 文件名工具

`src/utils/filename.ts` 负责：

- Unicode NFC 规范化。
- 控制字符、路径字符和跨平台非法字符清洗。
- Windows 保留设备名保护。
- 长度、尾随点和空格限制。
- 扩展名、时间戳、默认标题和 MIME 推断。

#### 图床工具

`src/utils/image-host.ts` 负责：

- HTTP(S) 端点校验。
- Header JSON 解析、名称检查和 CRLF 防护。
- multipart boundary、字段名、文件名和 MIME 构造。
- JSON/文本响应解析。
- 自定义字段路径、常见 URL 字段和可选删除令牌提取。
- 图片 Blob 的 SHA-256 计算。
- 删除端点与 JSON 请求体模板中的 URL、哈希、删除令牌替换。
- 返回地址协议校验。

网络请求仍由 Obsidian `requestUrl` 执行；工具层不访问网络。

#### 子导图公共流程

`src/main.ts` 中：

- `buildSubmapDocument()` 统一创建文档、复制可选内容和写入导航元数据。
- `persistSubmapDocument()` 统一目录创建、路径避冲突和文件写入。
- `createSubmapFile()` 创建空子图。
- `extractToSubmap()` 复制当前节点内容与后代。

## 6. 图片与图床流程

### 6.1 本地保存

粘贴图片时：

1. 解析父导图目录和配置的资源目录。
2. 清洗父文件名和扩展名。
3. 生成本地时间戳。
4. 选择无冲突路径。
5. 写入二进制资源。

### 6.2 上传

上传时：

1. 对图片二进制计算 SHA-256。
2. 按“图床 ID + SHA-256”查询上传缓存；命中时复用 URL，不发送重复请求。
3. 未命中时校验图床端点为 HTTP(S)。
4. 解析并校验自定义 Header。
5. 根据 `raw` 或 `multipart` 模式构造请求体并发送。
6. 优先读取 JSON，失败时解析文本。
7. 按自定义路径和后备路径提取 HTTP(S) URL，以及可选删除令牌。
8. 更新图片块的 `contentHash`、远程镜像来源与上传缓存。

内置预设会进一步处理服务差异：新增图床默认使用 Zipline，读取 `files.0.url` 和 `files.0.id`；历史缓存或旧图片块缺少 ID 时，通过当前 Token 查询 v4 文件列表按 URL/文件名补回。ImgBB 保存 `data.delete_url`；Freeimage.host 只配置上传，因为其公开 API 不返回可用于匿名自动删除的令牌。旧 Zipline v3/v4 预设会迁移为统一 Zipline。

### 6.3 本地文件删除条件

仅当以下条件同时满足时才尝试删除本地资源：

- 至少一个远程来源已成功保存到当前导图。
- 当前导图已经持久化。
- 资源是仓库内真实文件。
- 当前导图其他节点没有继续引用。
- 其他 `.mindmap` 文件也没有引用。

上传部分失败时保留本地文件。图片块可设置同行或独占一行；连续同行图片在导图、文章、通读和大纲中都会进入横向 flex 行并自动换行，避免每张小图仍占满整行。

### 6.4 远程删除

远程图床没有统一删除协议。“最后引用删除时同步清理图床”现在默认开启，但仍可手动关闭；只有图床预设或自定义配置提供删除 API 时才进入清理流程。上传与删除共用当前请求头，避免 Token 修改后删除仍使用旧配置。Zipline 使用文件 ID 路径删除；ImgBB 使用上传响应中的秘密删除链接；Freeimage.host 公开 API 不支持匿名自动删除。插件会扫描当前及其他 `.mindmap` 的同一 SHA-256 和远程 URL；确认最后引用消失后写入 1 分钟持久化删除队列，到期前撤销恢复会在最终复查时取消，插件重启后恢复队列。API 连通性产生的测试图也延迟 1 分钟清理。未启用任何有效图床时，图片右键菜单隐藏“上传到图床”。存在任一引用、遇到无法安全解析的文档、缺少删除能力或请求失败时均保留远程对象并提示。

### 6.5 图片编辑体验

导图和大纲中的外部图片粘贴严格使用粘贴瞬间的当前选中节点，不再优先读取可能残留的旧 DOM 焦点。完整“编辑节点内容”面板提供“+ 粘贴图片”、图片块内“粘贴剪贴板图片”和直接 `Ctrl/Cmd+V` 三种入口；图片保存到仓库后写入当前节点，并沿用现有自动上传排程。

快速编辑与完整“编辑节点内容”面板共用加粗、斜体、下划线和文字颜色快捷键。完整编辑器在文本框获得焦点时通过窗口捕获层优先拦截格式快捷键，并保留文本框和 `beforeinput` 回退；同一 `Ctrl/Cmd+B` 若同时产生 `keydown` 和 `formatBold` 输入事件，只应用一次，避免加粗被立即切换回去。图片预览窗口限制为 `86vw × 82vh`，最大 `1400 × 900 px`，避免遮住整个工作区。

## 6.6 截图与识别

插件设置中的“截图与识别”是紧随“AI 助手”的独立一级分类。普通截图与截图并识别分别拥有命令、编辑器快捷键、顶部工具栏按钮和节点右键入口，不再使用“截图后自动识图”开关。

桌面端由 `src/utils/desktop-capture.ts` 负责抓屏与编辑。Windows 优先使用启用 Per-Monitor V2 DPI 感知的 PowerShell/WinForms 路径抓取完整虚拟桌面，并记录全部显示器边界；编辑器在当前 Obsidian 根节点挂载全屏 `iframe`，通过“全部屏幕 / 屏幕 N”切换查看任意显示器。截图背景按比例适配而不拉伸，选区与导出使用虚拟桌面原始像素映射。选区默认覆盖当前屏幕完整范围，支持拖动、八方向缩放，并实时显示全局 `X / Y / 宽 × 高`。普通截图保持选区常驻，显示几何图形、画笔、箭头、文字、序号、马赛克、橡皮擦、识别并复制、下载、取消和复制工具栏，双击选区后复制并插入节点；截图并识别视觉上不显示底部工具栏，但必须保留与普通截图相同的完整工具栏和样式栏 DOM，并以 `opacity: 0`、`pointer-events: none` 隐藏，禁止生成空容器。倒计时沿用原有“秒后自动识别”胶囊提示，仅将数字显示为整数 `3、2、1`；鼠标悬停选区边框、拖动条或缩放手柄时暂停，离开这些区域或重新框选完成后从 3 秒重新开始。Esc 必须同时绑定 iframe 窗口和宿主窗口。普通截图的几何图形、画笔、箭头、文字和序号支持颜色、粗细及形状样式，箭头可切换为直线；文字输入框使用延迟稳定聚焦并兼容中文输入法；显示器名称由编辑器本地生成，避免 PowerShell 编码乱码。点击命令时先显示准备提示；禁止静默回退到操作系统交互式截图工具，抓取或覆盖层创建失败时显示明确错误并记录诊断阶段。

截图开始前由编辑器冻结插入目标；节点右键入口显式传入节点和内容块。普通截图只插入图片；截图并识别在插入后运行当前 AI 视觉或本地 OCR 流程；识别并复制只写入系统剪贴板，不修改导图。

## AI 助手

插件可将当前页面或右键节点分支转换为 Markdown，并发送到 OpenAI、DeepSeek、硅基流动、FreeLLMAPI 或自定义 OpenAI 兼容接口。AI 窗口提供普通问答、经预览确认的 AI 节点重整，以及完全离线的本地文字替换。AI 生成的 Markdown 必须先通过格式、大小、节点数和并发快照校验，用户确认后才替换当前页面或节点子树，并进入撤销历史。每个接口配置可使用最小请求执行连通性检测，检测不会发送导图正文。工具栏和 `Ctrl/Cmd+Shift+A` 默认使用当前页面；节点和页面空白处的右键菜单用于切换上下文范围。完整配置、安全和故障排查见 [AI_ASSISTANT.zh-CN.md](AI_ASSISTANT.zh-CN.md)。

## Codex 交付约束：源码包内部目录

完整源码压缩包的文件名应包含版本号和统一六位交付后缀，但压缩包内部第一层目录固定为 `obsidian-mindmap-studio/`。版本信息只出现在外部 ZIP 文件名和仓库版本元数据中，不得写入源码包内部目录名。交付前必须检查 ZIP 目录清单。
压缩包包含 `examples/` 等中文路径时，文件名必须以 ZIP UTF-8 标志写入。交付检查不仅要确认第一层目录，还要逐项确认中文文件名在压缩包目录和实际解压结果中均可读，不能依赖系统默认代码页。
Codex 交接包的外部文件名必须严格使用 `Codex-<版本>-handoff-<六位后缀>.zip`，不得包含项目名或其他额外字段。该命名要求只影响外部 ZIP 文件名，压缩包内部第一层目录仍固定为 `Codex/`。

全局设置中的“主题与外观”必须参考页面工具栏同名面板的信息架构。两者应至少保持“主题模板、画布与字体、节点与文字、连线与分支、阅读外观、代码外观”的对应关系；全局设置表达插件级默认值，页面设置表达当前 `.mindmap` 文件覆盖值。不得仅通过改名制造表面一致。

## 图片后台任务安全规则

- 图片加载全部失败时必须在导图、文章、通读和大纲原位置显示候选地址与复制操作。
- 粘贴图片必须在异步保存前冻结节点 ID；目标消失时停止插入，不得回退到根节点或其他节点。
- 恢复多图片自动上传时必须按文件批处理、按文件串行并使用汇总通知。
- 网络请求完成后只能用节点 ID 和图片块 ID 合并字段补丁；禁止把上传开始时读取的整份文档写回，禁止每张图片触发一次打开视图全量刷新。
- 文章前后页导航不得设置会触发悬浮提示的按钮 `title` 或按钮级 `aria-label`。
