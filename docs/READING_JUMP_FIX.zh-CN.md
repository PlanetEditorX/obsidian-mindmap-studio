# 节点反复跳转修复说明

## 问题表现

启用导图、大纲、文章和通读的统一阅读位置后，部分场景会出现以下现象：

- 点击子导图节点后，视图在父导图与子导图之间反复切换。
- 在文章、大纲或通读中点击节点后，页面先移动到该节点，又被滚动位置恢复逻辑拉回。
- 程序恢复滚动位置触发 `scroll` 事件，随后新的位置记录覆盖原目标，形成重复恢复。

## 根因

问题由三条链路叠加产生：

1. 程序修改 `scrollTop` 时，原有滚动监听仍将事件视为用户阅读操作。
2. 节点点击始终保存固定的 `viewportRatio = 0.35`，没有保留节点点击时的真实屏幕位置。
3. 用户显式打开子导图后，异步文章族上下文加载会读取旧的跨文件阅读位置，并立即导航回父导图。
4. 文章当前位置采集过去使用宽泛的 `[data-node-id]`；文章页壳本身也携带根节点 ID，章节间空白或布局变化时可能被误记为根节点，后续刷新便回到页首。
5. 每次定位留下独立的 20 ms 重试和双动画帧；快速连续点击时旧回调无法取消，会在新章节已经正确显示后再次写入旧目标。
6. 文章族上下文异步返回前，旧实现会先按当前物理文件和默认层级绘制一次正文；目录落地随后切换页面，跨文件子章节则可能先生成父章节编号与子文件根标题，再被完整上下文修正。
7. 目录配置判断过去只在 `showArticleToc` 已关闭时强制正文；跨文件显式目标早于上下文到达时，默认目录配置会再次覆盖目标，导致目标节点存在但页面仍落在目录/页首。
8. 物理文件替换时，上一文件的延迟恢复和布局观察未与新文档原子取消，旧 `scrollTop` 写入可能落到新页面。父导图元数据中的 `parentNodeId` 也可能缺失或因历史编辑过期。
9. 真实 1.40.4 日志进一步证明，`setOptions()` 在文章上下文刷新后仍以“旧 DOM 捕获位置 / 历史阅读位置”优先于本次显式目标：日志中 `render-decision.explicitTarget` 是点击章节，但随后 `window-mounted.latestTarget` 与 `selectedId` 变成文件根节点；返回父导图时同一恢复链又解析到刚离开的子文件，并主动发出新的 `open-path-request`。

## 修复策略

### 隔离程序滚动与用户滚动

`restoreReadingLocation()` 在修改文章或大纲滚动位置前调用捕获阻断器。阻断期间的 `scroll` 事件不会触发新的阅读位置写入，阻断会在布局稳定后自动解除。

### 保留点击节点的当前视口位置

文章、大纲和通读模式通过节点矩形与滚动容器矩形计算真实视口比例。下一次恢复时仍保持节点在原来的屏幕位置附近，而不是强制移动到 35% 高度。

### 显式导航优先

通过节点、目录、父级导航或跨模式定位打开另一个 `.mindmap` 文件时，视图会标记一次显式导航。第一次文章族上下文刷新优先使用当前文件和目标节点，并将它写入正确的文章族阅读位置键。

普通重新打开导图时不设置该标记，因此仍会恢复上次保存的跨文件阅读位置。

### 首帧落地与跨文件目标预排队

文章视图新增 `articleContextReady` 准备门。上下文未完成时只绘制与最终落地一致的目录或正文骨架，不调用真实文章渲染器；因此“显示目录”不会先闪出原始正文。上下文失败时使用当前文件构造安全回退，并结束准备态。

跨文件目录点击在切换 Obsidian 视图前，将目标文件和节点写入插件级短生命周期队列。新视图在创建编辑器前消费该目标，并同步建立显式 `ReadingLocation`，随后才刷新文章族上下文。首个真实窗口因此直接以目标节为中心，不再出现“第三章 + 子文件根标题”后又改成“第三节”的中间画面。

目录与正文切换共用同一落地方法和目标类型骨架。返回目录时取消离开章节的恢复任务，不保存正文锚点到本轮目录重绘，并在目录真实 DOM 完成后回到顶部。

### 显式目标覆盖目录配置与文件切换隔离

显式章节 `filePath + nodeId` 是正文导航事务的最高优先级。只要待聚焦章节存在，文章落地判断就直接选择正文，不依赖异步上下文中的 `showArticleToc`；上下文返回只能补充目录与编号。父级返回不再复用这一正文事务，而是使用独立目录意图。

切换物理文件时，编辑器先取消旧阅读恢复、入口动画帧、窗口扩展和 `ResizeObserver`，再在一次 `setDocument(document, false, options)` 中提交新文档与新文件路径。旧文件任务因此无法在新页面挂载后再写入页首位置。

返回父导图前，插件验证请求的父节点 ID 是否真实存在。若缺失或过期，则读取来源子导图关系并按规范化子导图路径扫描父节点树，恢复真实挂载节点；反查失败时退化为父导图根节点并显示提示。


### 父级返回与章节导航分离

真实 1.40.6 日志显示，工具栏手动返回目录能够正确产生 `directoryOnly=true`；错误来自子导图返回父导图时仍调用通用 `focusNode(parentNodeId)`。该函数为保证目录章节点击进入正文，会主动把 `articleLandingMode` 改成 `article`，因此父文件虽然保存了“显示目录”，仍会落到原始文章。

现在两种意图完全分离：

- 目录条目、上一篇和下一篇：章节正文意图，携带节点 ID 并调用正文定位。
- 顶部父级导航、底部“返回上一级”和文章模式 Esc：目录意图，不调用 `focusNode()`。

目录意图在插件层以短生命周期队列保存。父文件 `setViewData()` 在构造 `MindMapEditor` 之前消费它，先把内存文档的 `articleLandingMode` 设为 `toc`，因此第一帧就是目录骨架/目录页面。父节点 ID 仅在目录真实 DOM 挂载后用于查找 `a[data-node-id]`、滚动到该条目并短暂标记；它不会创建正文 `ReadingLocation`，也不会参与 5 KB 正文窗口。

调试日志应出现 `open-directory-request → queue-directory → consume-pending-directory → apply-pending-directory → show-directory → render-decision(directoryOnly=true)`；该链路不应出现针对父节点的 `focus-node-start`。

真实 1.40.8 日志进一步显示，上述目录意图和目录挂载都已成功，但紧接着的文章上下文刷新仍从整本导图的历史阅读位置中选中了刚离开的子文件，并主动发出新的 `open-path-request`。因此“目录导航意图”和“上下文恢复位置”必须同时受目录状态约束：只要当前为生成目录，`setOptions()` 的恢复目标固定为 `null`，不执行章节滚动，也不允许跨文件恢复。历史位置继续保留，只有用户再次主动点击目录章节时才会被新的显式目标替代。

调试事件 `set-options-restore-choice.articleDirectoryActive` 为 `true` 时，`chosenNodeId` 与 `chosenFilePath` 应为空，后面不得出现由恢复链触发的 `open-path-request`。

### 上下文刷新目标优先级

跨文件打开时，视图除了 `preferCurrentFileLocation` 外，还保留一次性的精确 `preferredCurrentNodeId`，直到对应文章上下文刷新完成。编辑器不再从可能被异步恢复修改的 `selectedId` 猜测目标。

上下文重建后的恢复位置按固定顺序选择：

1. 本次显式打开的当前文件精确节点；
2. 重建前真实 DOM 中捕获的当前锚点；
3. 文章族历史阅读位置。

只要第 1 项存在，就不会解析或导航到旧子文件。入口骨架也使用同样规则：启动本次过渡的显式章节优先于稍后到达的普通恢复请求。真正的新点击会取消旧入口帧并创建新的过渡，因此仍保持“最后一次点击生效”。

调试事件 `set-options-restore-choice` 会记录 `requestedPreferredNodeId`、`preferredNodeId`、`renderedNodeId`、`rememberedNodeId`、`chosenNodeId` 和 `chosenFilePath`。修复后，跨文件章节与父级返回的 `chosenNodeId` 必须等于本次请求节点，`chosenFilePath` 必须等于刚打开的物理文件。

### 文章窗口中的确定性目标挂载

大文件文章不会预先生成全部章节。恢复位置前，文章窗口控制器先检查目标节点是否位于当前真实 DOM；若不在，则围绕该节点重新建立前后各约 5 KB 的窗口。首次进入或目录跳转的轻量骨架仍在绘制时，目标 `ReadingLocation` 会先暂存，待真实窗口挂载后再恢复。随后只查询文档标题或精确的 `.mms-article-node[data-node-id]`，避免误命中目录项、页面容器或其他带相同属性的元素。

顶层目录点击当前物理文件内的章节时不再重新打开文件，而是直接调用 `focusNode()`，先把 `articleLandingMode` 切换到正文，再提交目标位置。显式目标通过 `pendingArticleFocusLocation` 由本轮文章重绘消费。

### 最后一次导航独占与布局稳定

文章位置采集只扫描 `.mms-article-document-title[data-node-id]` 和 `.mms-article-node[data-node-id]`，不再扫描文章页壳；章节边界使用下边界排除规则，避免同一像素同时归属上一章节。

每次语义恢复都会创建递增令牌。后续目录点击、跨文件跳转或重绘会取消前一次的定时器、动画帧和布局观察，因此旧任务不能在新目标到位后把页面拉回页首或其他章节。文章上下文刷新如果发生在事务期间，会优先沿用该事务的目标位置，而不是从正在变化的 DOM 重新采集。

目标定位完成后，`ResizeObserver` 在最多 5 秒内监听文章页尺寸。图片、表格、代码或字体晚到导致目标相对位置变化时，只重新应用当前事务的同一目标。用户通过滚轮、触摸、指针或键盘翻页开始阅读后，事务立即取消，不与手动滚动竞争。

## 运行调试记录

“管理配置 → 调试模式”开启后，插件以会话级内存日志记录用户事件和导航内部状态。结构化事件包括文件切换、目标排队/消费、文章上下文状态、目录/正文落地决策、窗口范围、目标 DOM 命中、滚动事务令牌、父节点解析和运行异常。正文、输入值、密钥与 AI 请求正文不会进入日志。

复现后从命令面板执行“复制 MindMap Studio 调试记录”，把 JSONL 粘贴给维护者即可还原事件顺序。启用时开始新会话，禁用或重启会清空；缓冲区有上限并对高频滚动节流。

## 数据兼容

本次修复不修改 `.mindmap` 文件结构，也不修改已保存的 `ReadingLocation` 字段。现有阅读位置会继续解析；新的点击位置只会使用更准确的 `nodeRatio` 和 `viewportRatio`。

## 验证场景

- 在导图中点击普通节点并切换到文章、大纲、通读。
- 点击带子导图的节点进入子导图，确认不会自动跳回父导图。
- 从子导图点击返回父导图，确认不会再次打开子导图。分别验证有效 `parentNodeId`、缺失 ID 和编辑后过期 ID，后两者应按子导图路径反查挂载节点。
- 在文章或通读中点击视口顶部、中部、底部节点并触发设置刷新。
- 切换模式后快速滚动，确认程序恢复完成后用户滚动仍可正常保存。
- 在目标章节上方放置延迟加载图片、表格和代码，确认内容撑高时目标章节仍保持稳定；滚轮、拖动滚动条或 PageDown 后不再自动拉回。
- 快速连续点击三个远端章节，确认最终只停在最后一次点击，等待 5 秒也不会再跳到旧章节或页首。
- 将顶层文章落地设置为“显示目录”，重复关闭和打开文件，确认始终先出现目录骨架并直接进入目录，不闪出原始正文。
- 从章节返回目录，确认存在与目录跳章节一致的轻量过渡，目录最终停在顶部而不是继承章节滚动位置。
- 从目录点击跨文件深层小节，确认首帧标题和编号就是目标小节，不先出现父章节编号或子文件根标题组合。
- 关闭并重新打开文件，确认阅读位置仍可恢复。
- 开启调试模式后复现一次章节回页首和父级返回，执行“复制 MindMap Studio 调试记录”，确认剪贴板为 JSONL、包含目标排队/消费与滚动事务事件，且不包含正文和输入内容。
