# MindMap Studio 代码库维护与优化说明

## 文档目的

本文是当前仓库的完整维护基线，说明代码结构、已完成优化、测试策略、风险控制、后续演进顺序和交付方式。它取代“逐版本把修复说明堆入 README”的方式：

- 产品当前能力由 `README.md` 描述。
- 历史变化由 `CHANGELOG.md` 记录。
- 数据兼容由 `MIGRATION.md` 与 `docs/DATA_MODEL.md` 记录。
- 开发、测试与 Git 流程由对应专题文档维护。

## 基线分析

### 主要问题

1. `src/main.ts`、`src/editor/editor.ts`、`src/core/model.ts` 和 `src/settings.ts` 体积较大，跨文件服务、输入校验和确定性转换容易混杂。
2. 文件名、时间戳、扩展名、MIME、Header、multipart 和图床响应解析原本直接写在插件入口类中，难以独立测试。
3. 创建空子导图与提取节点为子导图存在重复的文档初始化、导航元数据和路径构造逻辑。
4. `scripts/test.mjs` 综合覆盖广，但单文件过大，纯函数边界缺少独立、快速、可定位的测试。
5. 原 README 以版本标题连续堆叠，当前使用方式、开发入口和仓库结构难以快速找到。
6. 源码包包含 `.ua/`、`.local-test-build/` 和本地分析启动脚本，增加体积并可能把本地分析结果误提交。
7. 缺少统一 `verify` 命令、仓库清洁度检查、贡献指南、安全说明和结构化 PR/Issue 模板。

### 优化原则

- 不改变 `.mindmap` 数据版本和已发布字段语义。
- 先抽取不依赖 Obsidian 的纯逻辑，再考虑拆分高耦合 UI。
- 外部输入使用 `unknown` 与显式校验。
- 文件操作和图床删除继续保留原有安全条件。
- 重构必须有测试；文档必须描述当前状态，而不是只描述本次差异。
- 交付源码包不包含本地缓存和分析产物。

## 已完成代码优化

### 文件名工具层

新增 `src/utils/filename.ts`，集中处理：

- 跨平台非法字符与控制字符。
- Unicode NFC 规范化。
- 尾随句点、空格和 Windows 保留设备名。
- 最大文件名长度。
- 扩展名提取与后备值。
- 资源文件时间戳与默认导图标题。
- 图片 MIME 类型映射。

`src/main.ts` 保留薄封装以维持调用稳定，但不再重复实现规则。

### 图床工具层

新增 `src/utils/image-host.ts`，集中处理：

- HTTP(S) 上传端点校验。
- JSON Header 解析和扁平值限制。
- Header 名称、Header 值和 CRLF 注入防护。
- multipart 字段名、文件名、MIME 和 boundary 构造。
- JSON/文本响应载荷解析。
- 自定义字段路径与常见后备路径。
- HTTP(S) 返回 URL 校验。

网络请求仍由 Obsidian `requestUrl` 执行。工具层只负责确定性输入输出，避免与宿主 API 绑定。

### 子导图流程合并

`createSubmapFile()` 与 `extractToSubmap()` 现在复用：

- `buildSubmapDocument()`：创建文档、复制可选节点内容、同步兼容字段并写入父子导航元数据。
- `persistSubmapDocument()`：创建父导图专属资源目录、选择无冲突路径并写入文件。

这消除了两套路径与元数据逻辑漂移的风险。空子导图和提取子导图仍通过参数明确区分。

### 注释改进

新增模块和辅助方法使用具体 JSDoc，说明：

- 模块边界。
- 参数、返回值和异常。
- 安全或兼容原因。
- 测试注入点，例如固定 multipart boundary。

后续修改大文件中的模板化注释时，应逐函数替换为同等级别的语义说明，不建议一次性进行无行为收益的大规模注释改写。

## 测试体系

### 新增独立单元测试

`tests/filename.test.mjs` 和 `tests/image-host.test.mjs` 使用 Node 内置测试运行器。测试通过 TypeScript `transpileModule` 加载无依赖工具，不需要 Obsidian 环境。

覆盖成功、失败和边界路径，特别包括：

- 文件名注入、保留名、Unicode、长度和扩展名。
- 非 HTTP(S) 端点。
- Header 嵌套对象、非法名称和换行注入。
- 确定性 multipart 二进制请求体。
- 自定义路径、数组路径、纯文本 URL 和非法协议。

### 保留综合回归

原 `scripts/test.mjs` 继续作为广覆盖回归，不因新增单元测试而删除。拆分原则是：

- 新的纯逻辑进入独立测试。
- 跨模块行为继续留在综合回归。
- DOM 或 CSS 契约在缺少完整浏览器测试环境时保留源模式断言。

### 新增仓库检查

`scripts/check-repository.mjs` 检查：

- 必需文档存在。
- `.ua/`、`.local-test-build/` 和本地分析启动脚本未提交。
- 四个版本文件一致。
- 分层测试脚本与 `verify` 存在。
- README 是当前产品说明，而不是版本记录堆叠。
- `.gitignore` 包含构建、覆盖率和分析目录。

### 统一验证入口

```bash
npm run verify
```

执行顺序：

```text
单元测试
→ 综合回归
→ 文档检查
→ 仓库检查
→ TypeScript 类型检查
→ esbuild 生产构建
```

## 兼容性与风险

### 保持不变

- 插件版本仍为 `1.19.2`，本次交付作为优化基线，不擅自创建正式发布版本。
- `.mindmap` 数据版本和字段结构未改变。
- 图床配置字段、上传方法和请求体模式未改变。
- 子导图路径布局和双向导航字段未改变。
- 发布安装包仍为三个文件。

### 行为收紧

以下输入过去可能被宽松接受，现在会明确报错：

- 非 HTTP(S) 图床端点。
- 不是 JSON 对象的 Header。
- Header 嵌套对象、非法字段名或含换行符的值。
- 图床响应中的 FTP、`javascript:` 等非 HTTP(S) URL。

这是输入安全性和诊断质量改进。已有合法配置不受影响。

### 剩余技术债

1. `src/editor/editor.ts` 仍是最大单文件，后续应按导图画布、文章交互、剪贴板/拖放和工具栏拆分。
2. `src/main.ts` 仍同时承担生命周期、搜索、子导图、图床和迁移；可继续抽取服务对象，但需要 Obsidian 集成测试支撑。
3. 综合回归脚本应逐步转为按领域拆分的 Node test suite。
4. DOM 交互目前以手动冒烟和源码契约为主，后续可引入 jsdom 或宿主集成测试。
5. 自动生成函数参考较长，可增加按模块导航索引，避免单页查找成本。

## 推荐后续顺序

### 第一阶段：低风险拆分

- 抽取设置规范化纯函数。
- 抽取路径解析、父子导航匹配和安全删除引用扫描。
- 把综合测试中的纯函数断言迁移到领域测试文件。

### 第二阶段：编辑器职责拆分

- 导图画布与 SVG 连线控制器。
- 文章/大纲模式控制器。
- 节点选择、多选和拖放控制器。
- 键盘快捷键和剪贴板控制器。

每次只迁移一个职责，保持公共回调契约和数据模型不变。

### 第三阶段：集成测试

- 建立 Vault、Workspace 和 `requestUrl` 测试替身。
- 覆盖新建/重命名文件、子导图双向引用、图床部分失败和本地文件安全删除。
- 为三种显示模式建立 DOM 行为测试。
