# AI 编辑修改要求同步修复

## 问题

AI 窗口最初只使用一个文本框。切换操作模式时，界面虽然把字段标题从“问题”改成“修改要求”，但文本框内容仍是询问模式的默认问题：

```text
请分析这份思维导图，并回答我的问题。
```

因此进入“AI 整理并重新生成”后，用户看到的实际修改要求与当前操作不匹配。

## 修复行为

询问模式与 AI 编辑模式现在各自维护独立草稿：

- 首次进入“询问 AI”显示设置中的默认问题；
- 首次进入“AI 整理并重新生成”显示专用默认要求；
- 用户修改任一模式的内容后，切换到其他模式再返回会恢复该模式自己的草稿；
- 经过“本地文字替换”模式切换，也不会覆盖询问或编辑草稿。

AI 编辑默认要求为：

```text
按主题重新整理层级，合并重复节点，并重新生成清晰的导图结构。
```

## 实现边界

模式草稿逻辑位于 `src/ai/edit.ts` 的纯函数中，弹窗只负责调用：

- `createAiPromptDraftState()`：创建询问与编辑的初始草稿；
- `switchAiPromptDraft()`：保存离开模式的内容并返回目标模式应显示的内容。

这样测试不依赖 Obsidian DOM，也不再使用容易随重构失效的源码顺序正则。
